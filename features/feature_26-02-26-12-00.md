# Feature: Add Timestamps to Roles Table

**Date:** 2026-02-26

## Purpose

Add standard `created_at` and `updated_at` audit columns to the `roles` table, with `updated_at` automatically maintained via a PostgreSQL trigger. This is a foundational pattern that will be reused across future tables.

## Approach

### Database (Migration)

A new migration adds both columns as `TIMESTAMPTZ NOT NULL DEFAULT NOW()`. Rather than managing `updated_at` in application code, a reusable PostgreSQL trigger function (`set_updated_at`) is created using `CREATE OR REPLACE FUNCTION`. A `BEFORE UPDATE FOR EACH ROW` trigger on the `roles` table calls this function automatically whenever a row is updated.

The down migration reverses this: drops the trigger, drops the function, drops the columns.

### Rust (Application Layer)

- `Cargo.toml`: the `chrono` feature is added to sqlx, and `chrono` (with its `serde` feature) is added as a dependency.
- `RoleModel`: two new fields — `created_at: DateTime<Utc>` and `updated_at: DateTime<Utc>` — are added. sqlx maps `TIMESTAMPTZ` to `DateTime<Utc>` automatically.
- `role_service.rs`: the `query_as!` SELECT is updated to include `created_at` and `updated_at`, satisfying sqlx's compile-time struct/query check.

## Key Rust & PostgreSQL Concepts

- **`TIMESTAMPTZ`**: PostgreSQL timezone-aware timestamp; always stored in UTC.
- **PostgreSQL trigger functions**: A function that `RETURNS TRIGGER`, using `NEW`/`OLD` to access row data, attached via `CREATE TRIGGER`.
- **`chrono::DateTime<Utc>`**: The idiomatic Rust type for UTC timestamps; see [chrono docs](https://docs.rs/chrono).
- **sqlx compile-time checks**: `query_as!` verifies at compile time that the SELECT columns match the target struct's fields — a mismatch is a build error, not a runtime error.

## Reusability Note

The `set_updated_at()` trigger function is created with `CREATE OR REPLACE FUNCTION`, making it safe to call from multiple tables' migrations without conflict.
