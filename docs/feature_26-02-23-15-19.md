# Feature: Roles Module

**Date:** 2026-02-23

## Purpose

Introduce a `roles` module using a feature/domain-based structure. The module exposes a single
`GET` endpoint that returns all roles from the database. The database schema is managed via
sqlx migrations and seeded through a dedicated seed migration.

---

## Domain Model

**Table:** `roles`

| Column | Type | Constraints |
|--------|------|-------------|
| `id` | UUID | primary key, generated by Postgres (`gen_random_uuid()`) |
| `code` | varchar(1) | not null |
| `name` | varchar(20) | not null |

---

## Approach

### 1. sqlx CLI & Migrations

Install `sqlx-cli` with the postgres feature:

```
cargo install sqlx-cli --no-default-features --features postgres
```

Run migrations with:

```
sqlx migrate run
```

Create two migration files under `migrations/`:

- `0001_create_roles.sql` — creates the `roles` table
- `0002_seed_roles.sql` — inserts the initial role rows

Migration files are run in order and tracked by sqlx in a `_sqlx_migrations` table in the
database.

### 2. Project Structure

```
src/
  main.rs
  roles/
    mod.rs       — declares and re-exports the submodules
    model.rs     — the Role struct
    service.rs   — get_all_roles function
    handler.rs   — Axum handler for GET /roles
```

Wire the `roles` module into `main.rs` with `mod roles;`.

### 3. Model (`model.rs`)

Define a `Role` struct with fields matching the database columns. Derive `sqlx::FromRow` so
sqlx can map query results directly into the struct. Derive `serde::Serialize` so Axum can
serialize it to JSON. The `id` field should use the `uuid::Uuid` type.

### 4. Service (`service.rs`)

A single async function `get_all_roles` that accepts a `&PgPool`, runs
`SELECT id, code, name FROM roles`, and returns a `Vec<Role>` (or a `Result` wrapping it).
Use `sqlx::query_as::<_, Role>(...)` which maps rows directly into your struct via `FromRow`.

### 5. Handler (`handler.rs`)

An async Axum handler that:
- Accepts `State<PgPool>` as a parameter
- Calls `get_all_roles` from the service
- Returns `Json(roles)` — Axum's `Json` extractor serializes the `Vec<Role>` to JSON automatically
- Return type: `Result<impl IntoResponse, StatusCode>` to handle DB errors gracefully

### 6. Routing (`main.rs`)

Register the route in the Axum router:

```
Router::new()
    .route("/", get(handler))         // existing
    .route("/roles", get(roles::handler::handler))
    .with_state(pool)
```

## Key Rust Concepts

| Concept | Where it applies |
|---|---|
| `mod` and module tree | Wiring `src/roles/` into the project |
| `sqlx::FromRow` | Automatic row-to-struct mapping |
| `serde::Serialize` | JSON serialization of the model |
| `sqlx::query_as` | Typed query returning a mapped struct |
| `Json(...)` extractor | Axum response type for JSON |
| `Result<impl IntoResponse, StatusCode>` | Error handling in the handler |
