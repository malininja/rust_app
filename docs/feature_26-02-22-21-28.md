# Feature: sqlx Postgres Integration

**Date:** 2026-02-22

## Purpose

Replace the hardcoded string in the `GET /` handler with a live query result from a Postgres
database (`pos_rust`). This establishes a real database connection layer and demonstrates how
Axum shares application state with async handlers.

---

## Approach

### 1. Dependencies (`Cargo.toml`)

Add two new crates:

- **`sqlx`** with features: `postgres`, `runtime-tokio`, `tls-rustls`, and optionally `macros`
- **`dotenvy`** for loading environment variables from a `.env` file at startup

### 2. Environment Configuration

Create a `.env` file in the project root (make sure it is listed in `.gitignore`):

```
DATABASE_URL=postgres://user:pass@localhost/pos_rust
```

`dotenvy::dotenv()` should be called at the top of `main` so the variable is available before
the pool is created.

### 3. Connection Pool

At startup (inside `main`), create a `PgPool` using `PgPoolOptions`. Read `DATABASE_URL` from
the environment with `std::env::var`. The pool should be created before the Axum router is
built so it can be passed as shared state.

### 4. Sharing State with Axum

Use Axum's `State` extractor to share the pool with handlers. Wrap the pool in
`axum::extract::State` when registering the router, and accept `State<PgPool>` as a parameter
in your handler function.

### 5. Handler Logic

Inside the `GET /` handler:

1. Run `sqlx::query("SELECT 'Hello world' as message")` against the pool.
2. Call `.fetch_one(&pool).await` to execute the query and get a single row.
3. Extract the column value with `.get::<String, _>("message")`.
4. Return the string in the response body.

The handler return type should be `Result<impl IntoResponse, StatusCode>` so database errors
can be mapped to an appropriate HTTP status (e.g. `StatusCode::INTERNAL_SERVER_ERROR`) using
the `?` operator or `.map_err(...)`.

---

## Key Rust Concepts

| Concept | Where it applies |
|---|---|
| `State` extractor | Sharing `PgPool` across handlers without global state |
| `PgPool` | Thread-safe, async-aware connection pool from sqlx |
| `async`/`.await` | Database query is an async operation |
| Error propagation with `?` | Propagating sqlx errors up to the handler return type |
| `Result<impl IntoResponse, StatusCode>` | Idiomatic Axum handler return type for fallible operations |
