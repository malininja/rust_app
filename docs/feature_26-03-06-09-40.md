# Structured Logging and Request Tracing

**Date:** 2026-03-06

## Purpose

Replace ad-hoc `println!` calls with structured, levelled logging and add automatic HTTP request/response tracing using the `tracing` ecosystem.

## Approach

Use the two-crate logging pattern standard in the Rust ecosystem, plus `tower-http` for request tracing.

### Crates

- **`tracing`** — logging facade providing macros (`info!`, `debug!`, `warn!`, `error!`, `trace!`). Application and library code depends only on this.
- **`tracing-subscriber`** (with `env-filter` feature) — backend wired in at the binary level that formats and outputs log records.
- **`tower-http`** (with `trace` feature) — provides `TraceLayer` for automatic HTTP request/response span instrumentation.

### Setup Steps

1. Add the three crates above to `Cargo.toml`.
2. Initialize the subscriber once at the top of `main()` using `tracing_subscriber::fmt`.
3. Add `TraceLayer::new_for_http()` to the Axum router via `.layer(...)`.
4. Replace `println!` calls with the appropriate `tracing` macros at the correct log level.
5. Control output verbosity at runtime via `RUST_LOG` (e.g. `RUST_LOG=tower_http=debug cargo run`).

### Key Concepts

- **Structured fields:** `tracing` macros accept `key=value` pairs alongside the message (e.g. `info!(user_id = id, "request received")`).
- **Log levels:** `error` > `warn` > `info` > `debug` > `trace`.
- **`env-filter` feature:** Enables per-crate/module filtering via `RUST_LOG` (e.g. `RUST_LOG=my_crate=debug,tower_http=info`).
- **`TraceLayer`** emits spans automatically for each request covering method, URI, status code, and latency — no manual instrumentation needed.
