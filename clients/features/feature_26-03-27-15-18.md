# Feature: Personality Simulation Program

**Date:** 2026-03-27

## Purpose
Build a program in `clients/` that drives the `api/` by simulating three types of users (personalities). This exercises async Rust, HTTP clients, serde serialization, and tokio task concurrency.

## Personalities

- **Admin** (one, hardcoded credentials): Logs in at startup, fetches all users from `GET /users`, and spawns a concurrent personality for each based on their role.
- **SalesClerk** (one per Sales-role user): Loops continuously — fetches articles, creates an invoice, confirms it, then sleeps.
- **Warehouseman** (one per Warehouse-role user): Loops continuously — fetches articles, creates a goods receipt, confirms it, then sleeps.

## Approach

### Module structure
```
clients/src/
├── main.rs         — tokio entry point
├── admin.rs        — Admin struct: login → get users → spawn personalities
├── salesclerk.rs   — SalesClerk::run() loop
├── warehouseman.rs — Warehouseman::run() loop
├── api_client.rs   — Shared HTTP client (reqwest) with auth token
└── models.rs       — Serde DTOs mirroring the API's request/response shapes
```

### Key design decisions
- `ApiClient` holds the `reqwest::Client`, base URL, and optional JWT token. Wrapped in `Arc` for sharing across spawned tasks.
- Each personality receives a cloned `Arc<ApiClient>` pre-loaded with its own JWT (the user's credentials are not available — Admin logs in on their behalf... actually Admin creates the users, but in this version users are pre-existing in the DB).
- Personalities discover article IDs at runtime via `GET /articles`.
- Each loop iteration sleeps for 5 seconds between cycles.

## Key Rust Concepts
- `async/await` and `#[tokio::main]`
- `tokio::spawn` for concurrent tasks
- `Arc<T>` for sharing state across tasks
- `serde::{Serialize, Deserialize}` derive macros for DTOs
- `reqwest::Client` with `.json()` for request/response bodies
- `anyhow::Result` for error propagation in a binary crate
- `tokio::time::sleep` for non-blocking delays

## Dependencies
- `tokio` (features: `["full"]`)

- `serde` (features: `["derive"]`)

- `anyhow`

## API Endpoints Used
| Method | Path | Auth | Used by |
|---|---|---|---|
| POST | /login | none | Admin, (each personality logs in with their own creds) |
| GET | /users | Admin JWT | Admin |
| GET | /articles | any JWT | SalesClerk, Warehouseman |
| POST | /invoices | any JWT | SalesClerk |
| PATCH | /invoices/{id}/confirm | any JWT | SalesClerk |
| POST | /goods_receipts | any JWT | Warehouseman |
| PATCH | /goods_receipts/{id}/confirm | any JWT | Warehouseman |
