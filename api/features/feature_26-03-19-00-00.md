# Feature: goods_receipt Module

**Date:** 2026-03-19

## Purpose

Add a `goods_receipt` module to handle incoming stock from suppliers. Each receipt has a header (supplier name, confirmation status, soft-delete) and a list of line items (article reference, quantity, ordinal). The module follows the same layered architecture as the `articles` module.

---

## Database Migration

Two new tables, in a migration file timestamped after `20260316145911_articles`.

### `goods_receipt_heads`
| Column        | Type         | Notes                       |
|---------------|--------------|-----------------------------|
| id            | UUID PK      | `DEFAULT gen_random_uuid()` |
| supplier_name | TEXT NOT NULL|                             |
| confirmed     | BOOLEAN NOT NULL | `DEFAULT false`         |
| created_at    | TIMESTAMPTZ NOT NULL | `DEFAULT NOW()`     |
| updated_at    | TIMESTAMPTZ NOT NULL | `DEFAULT NOW()` + trigger |
| deleted_at    | TIMESTAMPTZ NULL | Soft delete             |

### `goods_receipt_items`
| Column     | Type                    | Notes                                  |
|------------|-------------------------|----------------------------------------|
| id         | UUID PK                 | `DEFAULT gen_random_uuid()`            |
| head_id    | UUID NOT NULL FK        | References `goods_receipt_heads(id)`   |
| ordinal    | INT NOT NULL            |                                        |
| article_id | UUID NOT NULL FK        | References `articles(id)`              |
| quantity   | NUMERIC(12, 4) NOT NULL |                                        |
| created_at | TIMESTAMPTZ NOT NULL    | `DEFAULT NOW()`                        |
| updated_at | TIMESTAMPTZ NOT NULL    | `DEFAULT NOW()` + trigger              |

- No `deleted_at` on items — they are logically excluded when the head is soft-deleted.
- Apply `on_update_timestamp()` trigger to both tables.

## Layers

### Models
- `GoodsReceiptHeadModel`: maps `goods_receipt_heads` columns via `sqlx::FromRow`
- `GoodsReceiptItemModel`: maps `goods_receipt_items` columns via `sqlx::FromRow`
- `NUMERIC(12,4)` maps to `rust_decimal::Decimal`

### DTOs
- `GoodsReceiptCreateDto`: `supplier_name: String`, `items: Vec<GoodsReceiptItemCreateDto>`
  - `GoodsReceiptItemCreateDto`: `ordinal: i32`, `article_id: Uuid`, `quantity: Decimal`
- `GoodsReceiptUpdateDto`: `supplier_name: Option<String>`, `items: Option<Vec<GoodsReceiptItemCreateDto>>`
- `GoodsReceiptResponseDto`: head fields + `items: Vec<GoodsReceiptItemResponseDto>`
  - `GoodsReceiptItemResponseDto`: item fields (no timestamps)

### Repository Trait Methods
- `get_all_unconfirmed()` → `Vec<GoodsReceiptHeadModel>`
- `get_by_id(id)` → `Option<(GoodsReceiptHeadModel, Vec<GoodsReceiptItemModel>)>`
- `create(supplier_name, items)` → `(GoodsReceiptHeadModel, Vec<GoodsReceiptItemModel>)`
- `update(id, supplier_name, items)` → `Option<(head, items)>` — items = replace all
- `soft_delete(id)` → `Option<GoodsReceiptHeadModel>`

Key behaviours:
- `create`: insert head, then insert all items.
- `update`: UPDATE head fields if `Some`, then DELETE existing items + re-INSERT new list if items is `Some`. Use a transaction to keep this atomic.
- `soft_delete`: `UPDATE heads SET deleted_at = NOW() WHERE id = $1 AND deleted_at IS NULL`. Items left as-is.
- All read queries filter `WHERE deleted_at IS NULL`.

### Service
- Wraps repository calls, maps `sqlx::Error` → `GoodsReceiptError` variants
- Returns DTOs (not models)
- `LOG_CONTEXT = "goods_receipt_service"`

### Error Enum (`GoodsReceiptError`)
Variants: `GetAllError`, `NotFoundError`, `CreateError`, `UpdateError`, `DeleteError`
Built with `thiserror`.

### Handlers & Status Codes
| Handler    | Method | Path    | Success       | Not Found | Error |
|------------|--------|---------|---------------|-----------|-------|
| get_all    | GET    | /       | 200 JSON(Vec) | —         | 500   |
| get_by_id  | GET    | /{id}   | 200 JSON      | 404       | 500   |
| create     | POST   | /       | 201 JSON      | —         | 500   |
| update     | PATCH  | /{id}   | 200 JSON      | 404       | 500   |
| delete     | DELETE | /{id}   | 204 No Content| 404       | 500   |

### Router
`Router::new()` with `.layer(from_fn_with_state(app_state, logged_in))` — same auth middleware as articles.
