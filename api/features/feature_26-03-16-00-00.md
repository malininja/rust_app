# Feature: Articles Module

**Date:** 2026-03-16

## Purpose

Add an `articles` module representing inventory items. Each article has a name and a unit of measure. All authenticated users (any role) can access the CRUD endpoints. Articles support soft deletion, consistent with the `users` module.

---

## Architecture

Follows the canonical 5-layer pattern from `src/roles/` and `src/users/`:

```
article_model → article_repository → article_service → article_handler → article_router
```

Files under `src/articles/`:
- `mod.rs`
- `article_model.rs`
- `article_repository.rs`
- `article_service.rs`
- `article_handler.rs`
- `article_router.rs`
- `article_errors.rs`
- `dtos/mod.rs`
- `dtos/create_article_dto.rs`
- `dtos/update_article_dto.rs`
- `dtos/article_response_dto.rs`

---

## Database Migration

New SQLx migration in `migrations/`:

1. Create Postgres ENUM type `unit_of_measure` with variants: `piece`, `kg`, `litre`, `metre`
2. Create `articles` table:
   - `id UUID PRIMARY KEY DEFAULT gen_random_uuid()`
   - `name TEXT NOT NULL`
   - `unit_of_measure unit_of_measure NOT NULL`
   - `created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()`
   - `updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()`
   - `deleted_at TIMESTAMPTZ NULL`
3. Attach `on_update_timestamp()` trigger to `articles.updated_at`

---

## Model Layer

- `UnitOfMeasure` enum: `#[derive(sqlx::Type)]` with `#[sqlx(type_name = "unit_of_measure", rename_all = "lowercase")]`. Variants: `Piece`, `Kg`, `Litre`, `Metre`. Also derives `Serialize`, `Deserialize`, `Debug`.
- `ArticleModel` struct: `#[derive(sqlx::FromRow, Serialize, Debug)]`. Fields mirror DB columns; `deleted_at` is `Option<DateTime<Utc>>`.

---

## Error Layer

`ArticleError` enum using `thiserror::Error`:
- `ArticleNotFound`
- `CreateArticleError`
- `UpdateArticleError`
- `DeleteArticleError`
- `DatabaseError`

---

## DTOs

- `CreateArticleDto`: `name: String`, `unit_of_measure: UnitOfMeasure` — both required
- `UpdateArticleDto`: `name: Option<String>`, `unit_of_measure: Option<UnitOfMeasure>` — all optional
- `ArticleResponseDto`: `id`, `name`, `unit_of_measure` — excludes timestamps and `deleted_at`. Implements `From<ArticleModel>`.

---

## Repository Layer

`ArticleRepository` trait (async, for testability) with:
- `get_all_articles()` — excludes soft-deleted rows
- `get_article_by_id(id: Uuid)`
- `create_article(name, unit_of_measure)`
- `update_article(id, name?, unit_of_measure?)` — uses `COALESCE` for partial updates
- `soft_delete_article(id)`

`PgArticleRepository` implements the trait using `sqlx::query_as!` with `pool: PgPool`.

---

## Service Layer

Standalone async functions generic over `R: ArticleRepository`:
- `get_all_articles`, `get_article_by_id`, `create_article`, `update_article`, `delete_article`

Maps `sqlx::Error` → `ArticleError`. Logs errors with `tracing::error!`.

---

## Handler Layer

Each handler takes `_claims: Claims` to enforce JWT authentication (any role). The `Claims` extractor returns `401` if the token is missing or invalid.

Handlers: `get_all`, `get_by_id`, `create`, `update`, `delete`.

---

## Router Layer

```
GET    /         → get_all
POST   /         → create
GET    /{id}     → get_by_id
PATCH  /{id}     → update
DELETE /{id}     → delete
```

Returns `Router<AppState>`. No middleware — auth handled by `Claims` extractor.

---

## App Assembly

In `src/lib.rs`, nest the articles router **after** the `auth_admin` middleware layer (JWT validity only, no admin check required):

```
.nest("/articles", articles::router())
```

Add `pub mod articles;` to module declarations.

---

## Key Rust Concepts

- Custom SQLx enum types (`sqlx::Type`, `type_name`, `rename_all`)
- Trait-based repository abstraction with `#[async_trait]`
- `COALESCE` pattern for partial SQL updates
- Generic service functions (`<R: ArticleRepository>`)
- Axum extractor as auth guard (`Claims` in handler params)
- `From<Model>` implementation on response DTOs
