# Feature: Users Module

**Date:** 2026-03-09

## Purpose

Add a `users` module to the existing Rust/Axum web service. The module handles user management with CRUD operations, soft deletes, password hashing, and a foreign key relationship to the `roles` table.

## Scope

- Database table with soft delete support and a FK to `roles`
- Five REST endpoints: list all, get by ID, create, partial update, soft delete
- Password hashing in the service layer
- Unit tests with mocked repository
- E2E tests with randomized data and explicit cleanup

## Approach

### Layer Structure
Follows the existing roles module pattern:
- `user_error.rs` — error enum for all failure cases
- `user_model.rs` — DB model, response DTO, and request DTOs
- `user_repository.rs` — trait + `PgUserRepository` implementation
- `user_service.rs` — business logic, generic over the repository trait
- `user_handler.rs` — Axum handlers
- `user_router.rs` — route definitions
- `mod.rs` — module exports and test config

### Key Design Decisions

| Concern | Decision |
|---------|----------|
| Password hashing | `argon2` crate (v0.5) — OWASP-recommended |
| `password` in `UserModel` | Yes, but `UserResponse` DTO omits it (no `Serialize` on `UserModel`) |
| Update semantics | PATCH — partial updates, password re-send not required |
| Hashing location | Service layer — business logic, not data access |
| E2E test cleanup | Explicit `DELETE FROM users WHERE username = $1` — transactions don't work across separate pool connections |

### API Endpoints

| Method | Path | Handler | Success |
|--------|------|---------|---------|
| GET | `/users` | `get_all` | 200 |
| GET | `/users/:id` | `get_one` | 200 / 404 |
| POST | `/users` | `create` | 201 / 409 |
| PATCH | `/users/:id` | `update` | 200 / 404 |
| DELETE | `/users/:id` | `delete` | 204 / 404 |

### Database

```
users
  id          UUID DEFAULT gen_random_uuid() PRIMARY KEY
  role_id     UUID NOT NULL REFERENCES roles(id)
  username    VARCHAR NOT NULL
  password    VARCHAR NOT NULL
  deleted_at  TIMESTAMPTZ NULL
  created_at  TIMESTAMPTZ DEFAULT NOW()
  updated_at  TIMESTAMPTZ DEFAULT NOW()
```

Two migrations:
1. `create_users` — table definition
2. `users_timestamps` — `updated_at` trigger only (function already exists from roles migration)

### Rust Concepts Involved

- `sqlx` — `query_as!` macro, `FromRow`, `fetch_optional`, `COALESCE` with explicit casts (`$1::uuid`) to avoid type inference errors
- `argon2` — `Argon2::default()`, `SaltString::generate`, `PasswordHasher::hash_password`
- `async_trait` — for mocking the repository trait in unit tests
- `axum` — `State`, `Path`, `Json` extractors; `StatusCode` responses
- `serde` — selective `Serialize`/`Deserialize` derives on DTOs
- `tracing` — `tracing::error!` before returning error responses in handlers
- `uuid` — `Uuid::new_v4()` for generating unique test usernames in E2E tests

### Testing Strategy

- **Unit tests** (`src/users/tests/user_service_test.rs`): mock structs implementing `UserRepository` via `#[async_trait]`, covering success and error paths per service function
- **E2E tests** (`tests/users_e2e.rs`): randomized usernames (`format!("test_{}", Uuid::new_v4())`), real role UUID queried from seeded data, explicit DB cleanup after each test
