# Feature: Roles Router + E2E Tests

**Date:** 2026-03-05

## Overview

Extract the roles routes into a dedicated router module, wire it into the main app router, and add end-to-end tests for the roles HTTP endpoints. Unit and e2e tests run independently via Cargo's built-in test targeting.

---

## Step 1: Create the Roles Router

**Goal:** Move route registration out of `main.rs` and into the `roles` module.

1. Create `src/roles/role_router.rs`
   - Define a public `router()` function that returns `Router<PgPool>`
   - Register `GET /roles` pointing at `role_handler::get_all`
   - Relevant types: `axum::Router`, `axum::routing::get`

2. Register the new module in `src/roles/mod.rs`
   - Add `pub mod role_router;`

3. Update `src/main.rs`
   - Remove the manual `.route("/roles", get(roles::role_handler::get_all))` line
   - Add `.merge(roles::role_router::router())` to the app router

---

## Step 2: Prepare the Model for Deserialization

The e2e test will deserialize the JSON response body into `Vec<RoleModel>`.

- Add `serde::Deserialize` to the `#[derive(...)]` on `RoleModel` in `src/roles/role_model.rs`

---

## Step 3: Add `reqwest` Dependency

Add to `Cargo.toml` under `[dev-dependencies]` (not `[dependencies]` — only needed for tests):

```
reqwest = { version = "...", features = ["json"] }
```

The `json` feature enables `.json::<T>()` for deserializing response bodies.

---

## Step 4: Create the E2E Test

**Location:** `tests/roles_e2e.rs` (top-level `tests/` directory, NOT inside `src/`)

This is Rust's integration test convention — each file here is compiled as a separate crate with access to your library's public API.

**Test structure:**
1. Connect to the database (use `DATABASE_URL` from environment, same as `main`)
2. Build the app router using your new `roles::role_router::router()` (and any other routes)
3. Bind a `TcpListener` on `127.0.0.1:0` — port `0` lets the OS pick a free port
4. Get the actual bound address via `.local_addr()`
5. Spawn `axum::serve(listener, app)` in the background with `tokio::spawn`
6. Use `reqwest::Client` to send `GET http://127.0.0.1:{port}/roles`
7. Assert `200 OK` status
8. Deserialize the body into `Vec<RoleModel>` and assert expected content

**Seeding:** For deterministic payload assertions, either:
- Seed known rows before the test and clean up after, or
- Assert only structural properties (non-empty, fields present) if seeding is complex

---

## Step 5: Running Tests Separately

Rust's Cargo provides built-in test targeting — no extra configuration needed:

| What to run | Command |
|---|---|
| Unit tests only | `cargo test --lib` |
| A specific e2e test file | `cargo test --test roles_e2e` |
| All e2e/integration tests | `cargo test --tests` |
| Everything | `cargo test` |

---

## Key Rust Concepts Involved

- **`Router::merge()`** — combines two routers into one
- **`TcpListener` on port `0`** — OS-assigned free port, standard for test servers
- **`tokio::spawn`** — runs the server in the background during the test
- **`[dev-dependencies]`** — dependencies only compiled for tests/benchmarks
- **`tests/` directory** — Cargo's integration test convention; separate from `--lib` tests
